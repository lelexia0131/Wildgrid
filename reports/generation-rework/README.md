# 荒野求生生成器改造与验证

验证日期：2026-10-19。环境：Windows、Node 24.19.0，直接运行 TypeScript，首张地图包含几何缓存初始化时间。耗时为生成函数的实际墙钟时间，不包含随后独立执行的唯一解复核；未测手机性能。

## 替换的主流程

旧流程的随机设施清单、随机补满剩余地形、最多多轮完整求解器修补、证明后逐格删地形重搜，以及 Worker 两秒一轮、持续换种子重建到 45 秒的流程均已移除。

新流程为自然地形规划 → 合法设施组合构造 → 行列提示 → 便宜质量筛选与逻辑路径验证 → 正式唯一解证明。地形采用连续水系、两岸森林和山脊生长，设施使用共享几何和真实规则。低、中难度从当前可行的设施角色选择下一项；高难度在保留草地走廊及通道后，优先覆盖选择最少的活动格，设施清单随组合形成。没有预制答案坐标表。

允许一次有上限的地形边界调整，只向已有同类区域扩展，保留设施合法性、餐车通道和至少 8 格草地；此阶段只检查候选几何，不调用正式搜索进行修复。

难度评分依据逻辑传播轮次、使用的规则种类、关系排除和成功的有限反证，另设每个等级的评分范围。设施数量范围、多格数量下限和奖励仍取原来的 `SURVIVAL_DIFFICULTIES`。候选数、节点数、密度仅用于诊断，不参与评分。低难度不使用假设，中难度最多 8 次、一层，高难度最多 24 次、两层；同类形状组的组合推演也有单独上限，溢出后放弃该项推断。

正式证明仍调用 `solveLevel(level, 2)`，且必须满足 `count === 1 && !aborted`。所有成功基准样本在生成过程中仅调用了一次正式证明，随后基准程序另做独立复核。逻辑推演没有读取隐藏答案；记录包含被排除的位置、确定的位置、假设和矛盾推导。

阶段预算：低、中难度单次设施构造最多 18 ms，高难度覆盖构造最多 35 ms，逻辑推演最多 45 ms，单次正式证明最多 180 ms。全程分别限制在 2.8 / 5.0 / 7.6 秒内，并有操作次数上限。Worker 看门狗另留启动余量，总计不超过 8 秒。取消立即终止 Worker；暂停终止计算，恢复使用原种子和剩余活动时间预算。搜索失败直接反馈，不在 UI 层自动换种子循环。

## 布局与推理抽查

查看了 [1 难布局](tier-1.png)、[6 难布局](tier-6.png)、[10 难布局](tier-10.png)。图中相同设施编号表示同一多格设施；地形与最终答案直接取自生成结果。水系、林地和山地均连续，高难地图保留草地走廊，没有棋盘式随机地形。

代表性 10 难地图的路径为：利用山地附近形状覆盖和瞭望塔互斥先确定三个瞭望塔；通过行列容量及关系排除缩小泳池、野餐桌、电塔和营地位置；确定泳池与野餐桌后继续排除木屋、篝火重叠候选；两次成功反证分别导出形状覆盖冲突和篝火候选不足，最后确定木屋及其余篝火。总计 10 轮传播、94 个主路径排除，分析 15 个有限假设，最深两层。并非每一次假设分析都形成一次有效反证。

完整记录见 [10 难推理记录](tier-10-reasoning.json)；另外保留了 1、6 难记录。布局抽查同时暴露出高难度偏好边缘走廊和三格营地的倾向，这是当前构造器的限制，不能把这些样本当作所有布局类型都已覆盖。

## 尚未解决的限制

10 难禁用三格营地的成功率仍不足，本次固定种子在预算内失败。高难度布局偏向边缘草地走廊，地形总量范围也较窄；进一步扩大开放布局和营地形状选择，应继续改进覆盖构造，而不是延长预算。暂停恢复会使用原种子重新构造，并保留剩余活动预算，不恢复 JavaScript 搜索栈。难度评分是可审计的规则代理指标，尚未经过真人解题校准。性能数据来自当前 Windows 环境，未验证手机及低性能设备。真实桌面 UI 端到端回归仍需在能启动 Electron 的环境完成。
